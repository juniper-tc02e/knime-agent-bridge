The final suite is serial because native tests share the active-project state. It uses only disposable synthetic workflows in a separate runtime/configuration/workspace. Local raw receipts and images remain under `runtime`; they are excluded from the public package because they include machine paths.

The evidence index caches ID/kind and file metadata, never payload authority. Every selected/direct read hashes current disk contents. Existing-file metadata changes trigger validation before filtering, including a kind change from previously unrelated history into a requested kind. Selected deletion and detected replacement during a read fail closed. Unselected deletion is detected on direct/all/original-kind reads; directory/stat observations are not atomic against hostile concurrent writers or restored metadata. Cold discovery still reads all existing records; filtered warm lookups avoid unrelated payload reads.

## Preservation and review

The implementation was developed in a separate Git worktree. The original installation's tracked-file hashes, three protected workflow archive hashes and two pre-existing KNIME process identities remained unchanged at the preservation check. No MCP registration, active runtime configuration, analytics data, fitted model state, run admission or watchdog policy was changed. Handover evidence records were verified before diagnosis. Private handover documents, planning notes, coursework, runtimes, credentials and vendor libraries are excluded from publication.

Independent source review found two material issues during development: alias/junction confinement and retention expiry hiding a known outcome. Both were corrected with regression tests; the final source review found no remaining critical or important blocker. Review approval is separate from the measured runtime acceptance results.

The initial complete run passed 173 of 174 tests; the existing canvas repair hit MCP's 60-second request timeout after history accumulated. The cause was repeated all-history evidence lookup, not a native canvas edit failure. A regression first failed, then passed after replacing the unfiltered task-manifest query. Indexed lookup tests also failed against the old store and passed after the correction. Native canvas repair then passed in 23.8 seconds, with before/after images inspected. A subsequent review required existing-file invalidation before kind filtering; final acceptance below includes that correction. No MCP/native/model watchdog timeout was raised.

The subsequent full integration run included the final metadata invalidation and passed the native canvas regression in 106.197 seconds overall, with individual MCP requests inside their existing limits. The remaining cancellation was test organization: data/Reader acceptance and thousands of independent lifecycle calls shared one deadline. Splitting those responsibilities retained every assertion and each 600-second deadline; both then passed. ## Reproduce and upgrade

Follow [SETUP.md](SETUP.md), using the tested installed KNIME and Edge plus a JDK for the source tests. Use a **disposable** workspace whose directory begins `workspace-w2-v04-`, inside a bridge `runtime` directory. Set `KNIME_AGENT_RUNTIME` explicitly, build, launch, wait for ready/alive health, then run:

```powershell
npm run test:beta
```

This bootstraps a native fixture, then enables the native, visual, reliability, v0.4 and installed-settings JVM tests and runs the entire suite serially. Source contract tests are labeled accordingly and are not presented as native runtime proof. The attached release ZIP includes the compiled JAR and a per-file SHA-256 manifest; check its archive checksum before extraction.

An active v0.3 JVM retains its loaded bundle. Trial v0.4 in a separate folder/runtime/workspace and MCP alias. Upgrade the active instance only after saving and deliberately relaunching it. Old session/project/context IDs must be rediscovered; replacing source files cannot add new native operations to a running process.
